## Methodology

1. Sourced the canonical task domains for an Agent Platform Engineer (level 40, AI Engineering family) from the public references catalogued in `.aicg/job-requirements.json → authoritative_references`.
2. Mapped each task domain to (a) the role on the level ladder that should own it primarily and (b) the curriculum module that will cover it.
3. Applied the **ownership rule** — assign primary coverage to the lowest-level role that genuinely requires the skill; higher-level tracks link back rather than duplicate. In particular, deferred:
   - *Down* to `ai-infra-junior-engineer` (level 10) for engineering-craft prerequisites (Linux / Git / Python / packaging / HTTP APIs).
   - *Down* to `llm-application-developer` (level 25) for LLM / prompt / tool-call / streaming fundamentals.
   - *Down* to `agentic-ai-engineer` (level 30) for build-altitude agent fundamentals (ReAct, framework mechanics, single-agent patterns, agent memory basics).
   - *Sideways* to `ai-eval-engineer` (peer, level 30, AI Engineering family) for application-layer evaluation methodology (judges, RAG eval, eval-gated CI/CD, online eval). This role owns the eval *platform*; that peer owns the eval *methodology*.
   - *Sideways* to `ai-infra-ml-platform` (peer, level 30, Infra family) and `ai-infra-mlops` (peer, level 25-30, Infra family) for the training / registry / MLOps plumbing this platform plugs into.
   - *Sideways* to `ai-infra-inference-engineer` (peer, level 35, Infra family) for the inference-serving substrate (vLLM / SGLang / TRT-LLM) the model gateway routes to. This role routes to that peer's serving layer; it does not operate it.
   - *Sideways* to `ai-infra-sre` (peer, level 30, Infra family) for the SRE substrate (observability backends, incident tooling) this platform integrates with.
   - *Sideways* to `senior-agentic-ai-engineer` (peer, level 40, AI Engineering family) for implementation-leadership on product-side multi-agent subsystems. That peer leads product-side subsystems; this role ships the platform both peers' teams consume.
   - *Sideways* to `agentic-safety-engineer` (peer, level 40, Governance family) for frontier-agent red-team methodology and dangerous-capability evaluation. This role integrates that peer's findings into the platform's safety plane; it does not author the methodology.
   - *Sideways* to `ai-risk-engineer` (peer, level 25, Governance family) for harm-model authoring and guardrail-effectiveness methodology. This role operates guardrails-as-a-service; that peer specifies what they must block.
   - *Up* to `ai-infra-architect` (level 45, Infra family) for cross-stack infra architecture and build-vs-buy portfolio strategy.
   - *Up* to `agentic-systems-architect` (level 48, AI Engineering family) for design-altitude agentic-system architecture across product lines.
   - *Up* to `ai-infra-senior-architect` (level 55), `ai-infra-principal-engineer` (level 60), and `chief-ai-officer` (level 70) for cross-platform strategy, roadmap governance, and executive sponsorship.
   - *Out of scope* to legal / privacy / compliance counsel and to SecOps / DFIR.
4. Flagged everything that has not yet been validated against in-window postings so the next cycle can demote any requirement whose evidence stays empty.

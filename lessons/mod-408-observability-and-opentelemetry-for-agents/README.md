# mod-408 — Observability and OpenTelemetry for Agent Fleets

**Estimated effort:** 12 hours · **Position in track:** eighth module (after [`mod-401`](../mod-401-agent-platform-position-and-paved-road-philosophy), [`mod-402`](../mod-402-agent-runtime-service-and-durable-execution), [`mod-403`](../mod-403-mcp-registry-and-tool-gateway), [`mod-404`](../mod-404-sandboxed-code-execution-plane), [`mod-405`](../mod-405-tool-and-permission-policy-plane), [`mod-406`](../mod-406-model-gateway-and-routing), [`mod-407`](../mod-407-evaluation-platform-and-regression-gating)).

Every plane the track has built — the runtime (mod-402), the MCP gateway (mod-403), the sandbox (mod-404), the policy plane (mod-405), the model gateway (mod-406), the evaluation plane (mod-407) — emits telemetry. Spans, logs, metrics, events, cost records, policy decisions, eval verdicts. Each plane is internally consistent. Across planes, they are not. Which attribute names a model. Which span is the "root" of an agent turn. Which event closes a tool call. Without a shared semantic contract, cross-plane telemetry is a join nightmare; without shared trace propagation, one agent request fragments into five disconnected traces; without a shared collector tier, every backend change is N re-instrumentations. That is the slice this module owns. By the end you can adopt the OpenTelemetry Semantic Conventions for Generative AI as the platform's instrumentation contract, engineer distributed trace propagation across runtime → model gateway → MCP server → sandbox → eval harness so one request produces one coherent trace, integrate OpenLLMetry / Langfuse / Arize Phoenix / Datadog LLM Observability / Grafana + Prometheus against the same semantic layer so each tenant chooses their backend without re-instrumenting, author conformance tests for teams emitting agent telemetry, and produce the EU AI Act Article 72 post-market-monitoring evidence slice from the platform's trace pipeline.

## Learning objectives

- Adopt the OpenTelemetry Semantic Conventions for Generative AI — `gen_ai.*` attributes, prompt / completion events, tool-call events — as the platform's instrumentation contract.
- Engineer distributed trace propagation across runtime → model gateway → MCP server → sandbox → eval harness so one request produces one coherent trace.
- Integrate OpenLLMetry, Langfuse, Arize Phoenix, Datadog LLM Observability, Grafana + Prometheus against the same semantic layer so each tenant chooses their backend without re-instrumenting.
- Author conformance tests for teams emitting agent telemetry so platform dashboards stay accurate.
- Produce the EU AI Act Article 72 post-market-monitoring evidence slice from the platform's trace pipeline.

## How to approach this module

1. Read the six chapters in order. The slice (01) is the frame; the vocabulary (02), propagation (03), and collector tier (04) are the three structural pieces the rest rests on; conformance (05) is the enforcement layer; the Article 72 view (06) is the external-facing export of the same pipeline.
2. Do exercise 01 before reading chapter 03. Chapter 02's attribute inventory makes more sense once you have translated one real span; chapter 03's propagation story is easier to reason about with that translation in hand.
3. Do exercise 02 before reading chapter 05. The conformance tests in chapter 05 are easier to write once you have broken propagation at least once, by hand, in a controlled way. Breaking one propagation site and watching the trace fragment is a lesson no reading can replace.
4. Keep the chapter 01 `TraceRecord` shape open while reading chapters 02–06. Every piece they build adds a field to the record. Losing the record as the connective tissue is how the plane devolves into disconnected dashboards.
5. Mark `<!-- needs-research: ... -->` on any claim you cannot verify. The OTel GenAI semconv is still maturing, the backend products ship product changes quarterly, and the EU AI Act's implementing acts land on no fixed timeline; the flag convention is consistent with mod-403 / 404 / 405 / 406 / 407 and blocks auto-merge, which is cheaper than silently guessing.

## Where the handoffs land

- **`ai-infra-sre` (peer, level 40, mod-410)** — consumes the pipeline's own health signals (collector drops, back-pressure, synthetic coverage), the fleet metrics (`gen_ai.client.token.usage`, `gen_ai.client.operation.duration`), and the guardrail event stream. SRE owns the alerting runbooks, the pager rotation, and the post-incident loop; the observability plane produces the signals and the dashboards.
- **`ai-eval-engineer` (peer, level 30)** — consumes the trace-and-replay store that the observability plane mirrors into the eval plane's content store. The eval plane's EvalRecord carries `trace_id` pointers into the observability pipeline; replays emit spans with `platform.replay_source_trace_id` attribute per chapter 03.
- **`ai-risk-engineer` (peer, level 25)** — reads the Article 72 evidence export and the guardrail-event stream as part of the harm-model review cadence. Flags attribute omissions on sensitive operations; the plane adopts the flag as a conformance-catalogue rule.
- **`agentic-safety-engineer` (peer, level 40, mod-411)** — emits guardrail verdicts as span events on the chat span, feeding Article 72's accuracy / robustness signal. The paved-road SDK's safety hook is what writes the event; the observability plane is the contract around what the event must contain.
- **`agentic-ai-engineer` (level 30) and `senior-agentic-ai-engineer` (peer, level 40)** — the primary emitters of telemetry on top of the paved-road SDK (mod-412). Their contract to the observability plane is "run the conformance tests on your service's PR and do not merge red"; the plane's contract to them is "the dashboards you depend on will not break because we renamed something quietly".
- **`agentic-systems-architect` (peer)** — pairs quarterly on the semantic-convention review, especially as OTel GenAI semconv matures and OpenInference converges. The vocabulary moves faster than this module can commit to and the review is a joint responsibility.
- **`agent-platform-leadership` (mod-413)** — owns the governance committee that signs off the Article 72 export surface and the retention policies per tenant tier; the observability plane is the mechanism, the governance committee is the accountability.
